# 配置、SQL 与脚本检查清单（OpenCodeReview）

## 审查与输出约定

- 只审查当前 <review_files> 中新增或修改的配置、SQL 或脚本。先按内容和文件类型选择下面的规则分区：配置规则不套用到普通 SQL，Shell 选项不套用到非 Shell 配置。JCR-00022 可检查上述文件中确实会执行的 Redis 命令。
- 使用 file_read 阅读同文件上下文，code_search/file_find 查找配置消费点、部署说明和脚本入口，file_read_diff 核对关联变更。没有提供的生产环境、数据库规模或执行权限不能自行假设。
- 通过 code_comment 提交，content 以 [JCR-000XX] 开头，仅用一到两句话说明问题与修复方向；path、existing_code、start_line/end_line 由 OCR 自动回填，不要在正文复述位置或代码证据；可用替换代码放入 suggestion_code。

## 配置文件（.yml/.yaml/.properties/.conf/.ini，以及允许审查的 .env 类型文件）

### JCR-00001 明文敏感信息
- 原级别：Critical
- severity：high
- category：security
- 判定：新增配置中直接保存实际使用的明文密码、私钥、Token、AK/SK 等凭据；结合配置消费方式排除非秘密标识。
- 排除：环境变量/密钥引用、明确虚构的占位值、普通连接主机名、单纯出现 password/token 等字段名。
- 修复：改为环境变量或密钥管理服务引用；报告不重复输出完整凭据，泄露凭据按实际情况轮换。

### JCR-00002 生产关键配置缺少保护
- 原级别：Major
- severity：medium
- category：bug
- 判定：确认配置会在生产激活，且当前改动对已知的线程池、连接池、超时、资源上限或其他关键行为引入可说明的性能/稳定性风险，同时缺少项目明确要求的保护或发布方案。引用具体配置值、使用位置和必要背景。
- 排除：仅缺少注释、未附变更说明、无法确认生效环境，或没有证据表明该值不合理；不要猜测生产流量和容量。
- 修复：按真实负载设置合理边界，必要时添加可观测性、灰度或开关，并补充关键变更说明。

### JCR-00003 默认关闭的安全配置被开启
- 原级别：Critical
- severity：high
- category：security
- 判定：当前改动启用默认关闭的危险能力，或关闭原有防护，并能证明在有效部署环境扩大未授权访问面，例如开放管理入口而缺少所需访问控制。先确认配置键、取值语义和框架版本。
- 排除：开启的是安全防护本身、配置只在受控开发环境激活、存在可验证的访问控制。不能根据 security/debug 等词或 true/false 字面值直接判定。
- 修复：恢复安全默认值，或补充与实际暴露面匹配的认证、授权和访问边界。

### JCR-00004 Spring Bean 覆盖开关被开启
- 原级别：Critical
- severity：high
- category：bug
- 判定：应用启动配置中新增或修改 spring.main.allow-bean-definition-overriding=true，或 YAML 等价嵌套形式，并在待审查环境生效。保留团队禁止依赖隐式覆盖兜底的规则；说明它允许同名 Bean 被覆盖，不能在没有同名定义证据时宣称已经发生错误覆盖。
- 排除：注释、只在测试环境生效的配置、最终有效配置仍为 false。环境变量占位符需结合默认值与部署说明确认，不猜测外部变量。
- 修复：删除不必要的开关，使用唯一 Bean 名称、条件装配或显式配置替换；@Primary/@Qualifier 用于候选选择，不能消除同名 Bean 注册冲突。多实例注入主题另见 JAVA-00012，但本条不依赖加载其他规则文件。

## SQL（.sql/.ddl/.dml）

### JCR-00010 DML 无 WHERE 条件
- 原级别：Critical
- severity：high
- category：bug
- 判定：新增或修改 UPDATE/DELETE 缺少有效的数据范围限定，执行路径可到达全表操作且没有明确全量维护意图/保护。读取完整语句，核对目标方言中的 JOIN/USING 等条件，不能只搜索当前行的 WHERE。
- 排除：受控且明确授权的全量重建/清理、其他有效限定、字符串或注释中的非执行 SQL。
- 修复：增加必要的限定与输入校验，检查影响行数，并按实际维护流程补充备份和回退保护。

### JCR-00011 SELECT *
- 原级别：Major
- severity：medium
- category：maintainability
- 判定：业务查询新增 SELECT * 或表别名.*，使实际返回列集合依赖表结构，违反团队显式列名约定。
- 排除：COUNT(*)、乘法、注释，以及仅用于 EXISTS 存在性判断且不输出业务列的 SELECT *。
- 修复：显式列出所需列并保留必要别名；不把所有 SELECT * 宣称为严重性能故障。

### JCR-00012 DDL 破坏性变更
- 原级别：Major
- severity：medium
- category：bug
- 判定：新增 DROP/TRUNCATE 或破坏数据/兼容性的 ALTER，结合迁移顺序、应用调用方和迁移说明确认会产生不可接受的数据损失或发布失败，且缺少实际需要的备份、恢复或分步方案。
- 排除：清理明确临时对象、已完成数据迁移并有保护的受控变更、项目采用可验证的前向修复流程。没有同名 rollback 文件本身不证明缺少恢复方案。
- 修复：先迁移和验证数据，再分步切换/删除；提供真实可行的恢复方案，不能承诺事务回滚能撤销所有数据库的 DDL。

## Shell 脚本（.sh/.bash/.zsh，按实际解释器判定）

### JCR-00020 高危删除命令
- 原级别：Blocker
- severity：critical
- category：bug
- 判定：新增递归删除命令，路径经过变量展开后可到达根目录、非预期目录或超出业务范围，且没有有效校验/边界保护。跟踪变量赋值、空值处理、引用、拼接、通配符和执行权限，给出具体危险展开路径。
- 排除：已验证的精确目标、有明确范围的临时目录清理、不可执行的示例。单独 rm -rf "$DIR" 在 DIR 为空时不等同删除根目录；需要检查如 "$DIR"/* 等实际展开和参数。
- 修复：校验非空、规范化路径并限制在允许目录内，正确引用参数并使用合适的选项分隔；不通过执行删除命令验证。

### JCR-00021 缺少安全执行选项
- 原级别：Major
- severity：medium
- category：bug
- 判定：按脚本解释器和执行路径确认关键命令失败、未定义变量或管道错误会被忽略并继续执行错误操作，且没有显式状态检查/trap/等效处理。说明实际被忽略的失败及其后果，不能只检查文件是否包含 set -euo pipefail。
- 排除：已有正确错误处理、明确允许失败的探测命令、脚本被调用方式已提供等效保障。
- 修复：按解释器兼容性使用适当严格选项或显式错误处理；pipefail 并非所有 /bin/sh 都支持，set -e 也不是所有上下文都生效。改变严格模式前核对脚本依赖的错误分支。

### JCR-00022 Redis 全量 Key 查询或批量删除
- 原级别：Critical
- severity：high
- category：performance
- 判定：配置、SQL 或脚本中的实际执行内容新增 Redis KEYS、FLUSHDB、FLUSHALL，或遍历/生成大量 key 后无边界删除。对于模板/脚本片段，先确认它会传给 Redis 执行，并检查目标环境和命名空间。
- 排除：非执行文档/字符串、普通 SQL DELETE、业务上有边界的精确 key 删除、明确隔离的测试实例操作。Redis DEL/UNLINK 本身不展开 glob；传入星号字面值不等于删除所有匹配 key，必须追踪调用工具是否先执行模式展开。
- 修复：使用精确 key、有界 SCAN、限速和业务白名单，或受控的版本化缓存失效；清库操作应有明确目标和独立维护授权，不能把 SCAN 当作无条件安全替代。
