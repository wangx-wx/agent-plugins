# Java 规范检查清单（OpenCodeReview）

## 审查与输出约定

- 仅对当前 <review_files> 中新增或修改的 Java 代码应用下列规则；不报告删除代码、未变更上下文或其他文件中的历史问题。测试目录 src/test/ 下的 Java 代码不适用。
- 逐项核对规则；上下文不足时使用 code_search 搜索定义和调用方，file_find 查找文件，file_read 读取上下文，file_read_diff 核对其他变更
- 只报告满足判定条件的问题；查不到代码、缺少注解、可能存在某个部署场景都不是违规证据。显式团队禁令可作为规则依据，但不能虚构运行时故障。
- 通过 code_comment 提交，每条评论的 content 以 [JAVA-000XX] 开头，仅用一到两句话说明问题与修复方向，只有能够给出正确替换片段时才填 suggestion_code。

## JAVA-00001 不必要的工作
- severity：medium
- category：performance
- 判定：新增或修改路径存在可避免的重复计算或 IO，例如循环内逐条数据库/RPC/HTTP 查询、相同参数反复读取同一数据源，且有批量化或复用空间。先确认调用确实执行 IO、循环规模和结果一致性要求。
- 排除：迭代间有必要依赖、查询条件随状态变化、底层已有批量/缓存处理，或微小固定次数且没有实际性能影响的场景。
- 修复：在语义一致的前提下批量查询后关联，或复用本次请求内的计算结果；不随意引入跨请求缓存和过期数据风险。

## JAVA-00002 未利用并发
- severity：medium
- category：performance
- 判定：多个 IO 操作无数据或顺序依赖，顺序执行对已知响应时间目标有明确影响，且项目允许并发执行。必须核对参数来源、事务/安全上下文、线程池容量、超时及下游限流。
- 排除：先校验再操作、先查询再用返回值继续查询、存在副作用顺序约束、并发收益或上下文传播无法确认。仅看到两次顺序调用不足以报错。
- 修复：使用项目已有的有界执行器或异步设施，保留超时、取消和错误处理；不直接建议阻塞 IO 使用公共线程池或 parallelStream，也不假定事务跨线程自动传播。

## JAVA-00003 内存问题
- severity：high
- category：bug
- 判定：可证明长期增长的无界集合、在线程复用场景未清理且持有数据的 ThreadLocal、当前代码负责关闭却泄漏的资源，或已知大数据量被无界加载到内存。
- 排除：框架负责资源生命周期、已有 try-with-resources/finally 清理、集合或数据规模有明确上限。
- 修复：限制容量与生命周期、在实际所有者处释放资源；按数据规模采用分页或流式处理。

## JAVA-00004 抽象泄漏
- 原级别：Major
- severity：medium
- category：maintainability
- 判定：新增代码违反可从架构文档或现有实现确认的分层约定，暴露内部表示并造成调用方耦合，例如该项目明确禁止的 Controller 直连 DAO、直接暴露数据库 Entity。
- 排除：项目有意使用该设计且没有相应约束。不能仅因返回 Entity 或暴露某种类型就声称有功能或安全故障。
- 修复：沿用项目既有 Controller/Service/Repository 边界，使用适当 DTO/VO 或受控接口；避免为简单场景引入无必要的层次。

## JAVA-00005 Null 风险
- severity：medium
- category：bug
- 判定：明确可到达的 null 返回/输入流向解引用或拆箱，例如 Map.get() 缺项后直接使用、可空查询结果的链式调用。读取返回契约、调用方和已有保护，说明触发条件。
- 排除：已有控制流保证非空、框架或类型契约保证非空、只缺少形式上的判空而无可达 null 路径。
- 修复：在合适边界校验、处理不存在的结果或按项目习惯返回空集合；Optional 和工具类不是必须采用的修复形式。

## JAVA-00006 明文敏感信息
- severity：high
- category：security
- 判定：新增代码包含实际使用的密码、带凭据的连接串、API Key、Token、AK/SK 等硬编码凭据。
- 排除：环境变量占位符、明确虚构的示例、非秘密的主机名/连接地址、字段名称本身。
- 修复：改用环境变量、配置中心的密钥引用或密钥管理服务；报告正文不重复传播完整密钥，必要时提醒轮换已经泄露的凭据。

## JAVA-00007 并发安全问题
- 原级别：Major
- severity：medium
- category：bug
- 判定：确认共享可变对象存在并发访问，再检查数据竞争、check-then-act、复合操作或不安全集合。说明共享对象在哪里创建、哪些调用路径并发访问、现有同步为何不足。
- 排除：方法内不逃逸的局部对象、只读/不可变对象、已正确同步、明确单线程执行的阶段。
- 修复：根据操作语义选择原子方法、锁或线程安全结构；单纯换成 ConcurrentHashMap 不保证跨多个操作的原子性，CopyOnWriteArrayList 不适用于所有写入模式。

## JAVA-00008 事务使用问题
- severity：medium
- category：bug
- 判定：结合 Spring 版本、代理方式和实际调用链确认事务异常，例如代理模式下自调用绕过事务、方法无法被当前机制拦截、应回滚的受检异常未回滚，或事务内慢 IO 对连接/锁持有产生明确影响。
- 排除：调用方已经建立所需事务、使用其他有效的事务织入方式、异常本就不应回滚、只有未写 rollbackFor 而无业务回滚要求。
- 修复：修正实际事务边界或调用方式，按业务指定回滚异常；移动 IO 时保留一致性要求，不无条件添加 rollbackFor=Exception.class。

## JAVA-00009 API 设计问题
- severity：medium
- category：maintainability
- 判定：依据项目约定，检查超过 5 个参数却未合理封装、Controller 承载明显业务流程、Map 返回值导致契约不明确等问题，并说明具体维护成本或误用点。
- 排除：框架回调/第三方接口签名无法修改、明确设计的动态响应、少量参数提取或简单委托。不要将所有 Map 返回值或 Controller 条件语句视为违规。
- 修复：超过 5 个参数时评估 Request DTO；将实际业务流程放回合适的 Service，保持现有接口兼容性。

## JAVA-00010 @Async 方法字段访问不一致
- severity：high
- category：bug
- 判定：类内同时存在 static 桥接字段和实例注入字段，异步路径访问后者时，必须进一步证明存在手动 new 的非托管实例、初始化完成前发布/调用，或其他实际未注入路径，导致可达的空字段访问。
- 排除：正常由 Spring 创建并完成依赖注入的 Bean。@Async 改变执行线程，不会天然使实例依赖未注入；混用两类字段、热部署的猜测都不是 NPE 证据。
- 修复：保证调用真实托管实例，优先构造器注入、显式依赖传递和正确生命周期；不要仅为了风格一致而新增 static 桥接。

## JAVA-00011 @PostConstruct static 桥接遗漏
- severity：high
- category：bug
- 判定：存在实际被使用的 static 依赖字段，当前变更未给它赋值或使用早于其初始化，并能从调用链确认随后会解引用空值。必须指出遗漏赋值的字段、赋值位置和使用路径。
- 排除：新增 @Autowired 实例字段被正常托管实例使用、已有初始化覆盖实际 static 字段、单凭出现 @Async/@Scheduled/消息监听器推断非 Spring 管理。
- 修复：优先移除对 static 服务定位的依赖、改为构造器注入；必须兼容遗留桥接时，只修正实际被使用字段的初始化并处理生命周期，不要求所有注入字段复制到 static。

## JAVA-00012 Redis 全量 Key 查询或批量删除
- severity：high
- category：performance
- 判定：生产路径新增 KEYS/RedisTemplate.keys("*")，或确实会无边界遍历/删除全部或大范围 key 的逻辑。对 del/unlink/delete 的批处理，检查实际 key 集合来源、规模、限流和命名空间。
- 缓存注解：@CacheEvict(allEntries=true) 需要结合 CacheManager/CacheWriter、缓存名称与前缀配置判断实际影响；缓存名中的星号不必然是 Redis glob。只有确认是 Redis 且清理范围/流量风险符合本规则时报告，不能把清理特定缓存等同清空整个 Redis。
- 排除：测试代码、明确有界的精确 key 清理、有业务边界和保护的受控失效流程。不得把 SCAN 视作自动安全：仍需限定总量和删除范围。
- 修复：精确 key、业务白名单、有界 SCAN 和限速，或版本化缓存失效；同时评估缓存重建流量。

## JAVA-00013 消息消费者 info 日志输出消息体
- 原级别：Critical
- severity：high
- category：security
- 判定：消息消费方法/Handler/监听器新增 info 日志，确实输出完整原始 payload 或完整反序列化内容。若日志参数是对象，先检查 toString/序列化实现，不能仅凭变量名认定输出完整消息体。
- 规则性质：保留团队禁止在 info 输出完整消息体的要求；说明潜在数据暴露和日志规模，不在没有字段证据时断言含密码或特定个人信息。
- 排除：仅输出 messageId、业务主键等允许的定位字段，或对象实际已输出受控摘要。完整内容已脱敏但仍完整输出时，可按团队日志量约定报告，不虚构未脱敏泄露。
- 修复：info 仅保留必要定位字段；如需 debug 排查，仍须脱敏、采样和开关保护，debug 本身不消除秘密泄露风险。

## JAVA-00014 消息消费者 info 日志输出消息体基本信息
- severity：low
- category：performance
- 判定：消费路径新增对 body size、payload length、encoding、schema、摘要 hash、字段数量等元信息的逐消息 info 输出，未见采样/限频或低频保障。按原团队规则提醒评估消息量，不宣称已经发生磁盘故障。
- 排除：已有采样/限频、仅异常或明确低频路径输出、仅输出团队允许的链路定位字段。
- 修复：结合真实吞吐量采用采样、debug 或指标聚合；同一日志若已按 JAVA-00014 报告，不重复使用本规则。

## JAVA-00015 禁止使用 fastjson
- severity：high
- category：security
- 判定：新增或修改代码引入 com.alibaba.fastjson 包（fastjson 1.x），或使用能够确认归属该包的 API。先解析 import、全限定名或类型定义，不能仅凭 JSON/JSONObject 类名判断。
- 排除：com.alibaba.fastjson2、Jackson/Gson、同名自定义类型、仅删除旧调用的变更。
- 规则性质：这是保留的团队依赖禁令。单纯序列化或普通 API 调用不能证明存在可利用的反序列化 RCE；具体漏洞需要版本、配置和输入路径证据。
- 修复：优先使用项目已有 Jackson/Gson，或经兼容性验证迁移 fastjson2；核对日期、数字、空值和字段命名等序列化行为。

## JAVA-00016 异常处理缺陷
- severity：medium
- category：bug
- 判定：新增或修改的 catch/finally、兜底分支或错误返回路径，存在下列可证明的缺陷之一：(a) 捕获后既未记录也未改变状态、异常被静默吞掉；(b) 分支条件不完备，某个可达状态走入空分支或 else 后既不记录也不处理；(c) 先返回“成功”或已提交部分结果，随后步骤抛异常，导致回调方拿到 success 而实际未完成。必须说明可达的具体状态组合与后果。
- 排除：已有日志或状态回滚、明确的“允许失败”探测调用、外层统一异常处理已覆盖且语义正确、仅风格差异（如 catch 变量未使用）。
- 修复：补齐缺失分支和失败状态，或记录失败原因并按业务决定是否回滚；不要让异常改变控制流却不改变调用方可见的结果。
- 与 JAVA-00005 的边界：本规则针对“异常/失败路径本身处理不当”；JAVA-00005 针对“null 流入解引用或拆箱”。同一处问题只按更贴切的一条报告，不重复。
